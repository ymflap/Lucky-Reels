
# Lucky-Reels

## 1. تعريف المشروع

Lucky-Reels لعبة Slots عبر الويب تتكون من ثلاث بكرات ورموز ومكافآت، وتُطوّر بهدف تقديمها إلى Raise Engine لتوزيعها على مشغّلي الكازينو.

المنصة المستهدفة الأولى:
https://www.raise-engine.com/

المنصة البديلة:
https://stake-engine.com/

المشروع في مرحلة التخطيط، ولم يبدأ التنفيذ البرمجي بعد.

## 2. نموذج التشغيل المعتمد

المطور مسؤول عن:
- تصميم اللعبة وبرمجتها.
- تجهيز الواجهة والأصول الرسومية.
- إعداد النموذج الرياضي ووثائقه.
- إجراء الاختبارات الفنية.
- معالجة العيوب في الكود الذي يطوره.
- تقديم اللعبة والتعاون في مراجعتها واعتمادها.

تتولى Raise Engine، وفق شروطها والعقد المقبول:
- استضافة اللعبة المقبولة وتشغيلها ضمن بنيتها.
- مراجعة جودة اللعبة والنموذج الرياضي.
- تنسيق الاختبارات والاعتمادات اللازمة للأسواق التي تختارها.
- توزيع اللعبة على مشغّلي الكازينو ومجمّعات الألعاب.
- إعداد تقارير إيرادات اللعبة وحساب حصة المطور.
- دفع مستحقات المطور وفق شروط الاتفاقية.

يتولى مشغّل الكازينو، بحسب اتفاقياته ومتطلبات الترخيص:
- إدارة علاقة اللاعبين وحساباتهم.
- إدارة أرصدة اللاعبين والمحافظ المالية.
- معالجة الإيداع والسحب.
- التحقق من اللاعبين والامتثال لمتطلبات التشغيل الواقعة على عاتقه.
- تطبيق ضوابط اللعب المسؤول والحماية المطلوبة.

تُحدّد المسؤوليات النهائية من خلال العقود واللوائح المطبقة، ولا يُفترض أن Raise Engine تتحمل تلقائيًا جميع التزامات مشغّل الكازينو أو المطور.

## 3. المصادقة والحسابات والأموال

لا ينشئ مشروع Lucky-Reels نظامًا مستقلًا لتسجيل حسابات اللاعبين أو تسجيل دخولهم.

لا ينشئ المشروع:
- قاعدة بيانات لحسابات اللاعبين.
- نظام كلمات مرور أو جلسات دخول للاعبين.
- محفظة مالية خاصة بالمشروع.
- نظام إيداع أو سحب.
- لوحة إدارة مالية أو تعديل أرصدة.
- دفتر حركات مالية خاصًا بالمشروع.
- واجهات API مالية مستقلة.

تعتمد هوية اللاعب وسياق الجلسة وآلية الاتصال بخدمات التشغيل على التكامل الرسمي الذي توفره المنصة.

تُدار أموال اللاعبين وحساباتهم من خلال مشغّل الكازينو وفق مسؤولياته واتفاقياته.

قد تطلب Raise Engine من المطور التحقق من هويته وعنوانه وبيانات استلام مستحقاته. هذا إجراء خاص بحساب المطور لدى المنصة، وليس وظيفة داخل اللعبة.

## 4. الإيرادات والملكية

يحتفظ المطور بملكية اللعبة الفكرية وفق الاتفاقية.

تمنح اللعبة حقوق التوزيع اللازمة وفق شروط المنصة التي تقبلها.

توضح شروط Raise Engine المنشورة حصة Full Launch بنسبة 5% من Net GGR وفق تعريف العقد، مع تسوية شهرية وحد أدنى للدفع قدره 100 دولار أو ما يعادله وفق الشروط المنشورة.

هذه الشروط لا تضمن قبول اللعبة أو تحقيق دخل.

قبل القبول يجب مراجعة:
- اتفاقية المطور النهائية.
- طريقة حساب الإيرادات والتسويات.
- شروط الدفع ووسيلته والضرائب.
- حقوق الملكية والتوزيع.
- التزامات المطور والمسؤوليات القانونية.
- شروط الانسحاب وإنهاء التوزيع.

## 5. التقنيات المخططة

- Frontend: React + TypeScript.
- Build: Vite.
- Graphics: HTML5، مع إمكانية استخدام PixiJS إذا لزم.
- Math Model: JSON وفق المخطط الرسمي للمنصة.
- Testing: Vitest.
- Repository: GitHub.
- CI: GitHub Actions.

لا يُضاف خادم مستقل أو قاعدة بيانات أو نظام مصادقة إلا إذا تطلبت وثائق التكامل الرسمية وظيفة محددة لا توفرها المنصة.

## 6. معمارية اللعبة

تتكون اللعبة من طبقات مستقلة:

1. واجهة اللعبة: البكرات والرموز والحركة وعرض النتائج.
2. تعريف الرموز: خصائص الرموز وقواعد العرض.
3. النموذج الرياضي: احتمالات الرموز وقواعد الفوز والمكافآت.
4. طبقة تكامل المنصة: واجهة منفصلة للاتصال بآلية التشغيل المعتمدة.
5. تعريف اللعبة: الاسم والمعرف والإصدار.
6. الاختبارات: التحقق من قواعد اللعبة والنموذج الرياضي والتكامل.
7. وثائق التقديم: المعمارية والرياضيات والاختبارات ومتطلبات التسليم.

لا تكون واجهة المتصفح وحدها مصدرًا موثوقًا لنتائج اللعب بأموال حقيقية.

لا تُخترع واجهات API أو آلية محفظة أو طريقة تحديد نتائج الجولة قبل مراجعة وثائق المطور الرسمية.
