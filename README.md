Lucky-Reels

1. تعريف المشروع

Lucky-Reels لعبة Slots عبر الويب، مبنية باستخدام React وTypeScript، وتستهدف التقديم إلى Raise Engine أولًا، مع Stake Engine كخيار بديل.

- المستودع: https://github.com/ymflap/Lucky-Reels
- الفرع الرئيسي: "main"
- منصة التقديم الأولى: https://www.raise-engine.com/
- المنصة البديلة: https://stake-engine.com/
- إجمالي جرد الملفات الأساسي: 25 ملفًا
- الملفات المنجزة حاليًا: 10 من 25
- المرحلة الحالية: بناء الأساس والواجهة الأولية للعبة.

نجاح البناء لا يعني قبول اللعبة من أي منصة أو اعتمادها للعب بأموال حقيقية.

2. القرارات المعتمدة لتصميم اللعبة

نوع اللعبة

- لعبة Slots كلاسيكية بثلاث بكرات رأسية.
- يظهر رمز واحد من كل بكرة في صف أفقي واحد.
- عدد الرموز الظاهرة في نتيجة الجولة: ثلاثة رموز فقط.
- يختار اللاعب رهانًا تجريبيًا ثم يضغط "SPIN".
- تتحرك البكرات وتتوقف لإظهار النتيجة.
- يتحقق الفوز فقط عندما تتطابق الرموز الثلاثة.
- إذا اختلف رمز واحد أو أكثر، يخسر اللاعب الرهان التجريبي للجولة.
- تُحسب المكافأة التجريبية وفق قواعد المكافآت المحددة في الكود، إلى حين اعتماد النموذج الرياضي النهائي.

الطابع البصري

الهوية البصرية مستوحاة من مصر القديمة والأساطير المصرية، مع رموز مثل:

- عين حورس.
- الجعران الذهبي.
- مفتاح الحياة "Ankh".
- زهرة اللوتس.
- الجوهرة الملكية.
- تاج الفرعون.

يُفضّل إنشاء الرسومات الأصلية باستخدام SVG وCSS أو رسومات أصلية أخرى بدل نسخ أصول ألعاب تجارية. يجب التحقق من حقوق أي أصل خارجي قبل استخدامه.

ميزات غير معتمدة حاليًا

لا تُضاف الميزات التالية تلقائيًا:

- Wild أو Scatter.
- Free Spins.
- Cascade أو Match-3.
- مضاعفات إضافية أو Jackpot.
- خطوط دفع متعددة.
- قواعد فوز لا تتفق مع قرار تطابق الرموز الثلاثة.

أي توسعة مستقبلية تتطلب قرارًا واضحًا وتحديث التوثيق قبل التنفيذ.

3. الوضع التجريبي والمال الحقيقي

النسخة الحالية نموذج أولي تجريبي يستخدم رصيدًا افتراضيًا داخل الواجهة.

- الرصيد التجريبي الابتدائي في واجهة اللعبة: 1000.
- خيارات الرهان التجريبي: 5 و10 و25 و50.
- لا توجد أموال حقيقية أو عمليات دفع داخل النسخة الحالية.
- الرصيد التجريبي ليس محفظة مالية ولا يمثل أموالًا قابلة للسحب.
- المكافآت الحالية ليست نموذجًا رياضيًا معتمدًا أو ضمانًا لـRTP محدد.

لا يُسمح بتفعيل اللعب بأموال حقيقية قبل استكمال متطلبات المنصة والموافقات والاختبارات والنموذج الرياضي المعتمد.

4. الحسابات والأموال ومسؤوليات التشغيل

لا ينشئ Lucky-Reels نظامًا مستقلًا لحسابات اللاعبين أو أموالهم.

لا يتضمن نطاق اللعبة المستهدف:

- تسجيل حسابات اللاعبين أو إدارة كلمات مرورهم.
- قاعدة بيانات مستقلة لحسابات اللاعبين.
- محفظة مالية خاصة باللعبة.
- الإيداع أو السحب.
- لوحة تحكم لتعديل أرصدة اللاعبين.
- دفتر حركات مالية مستقل.
- واجهات مالية مستقلة غير موثقة.

تعتمد هوية اللاعب وسياق الجولة والاتصال بخدمات التشغيل على التكامل الرسمي الذي توفره المنصة المستهدفة. وتُحدّد المسؤوليات النهائية بموجب شروط المنصة واتفاقياتها والقوانين المطبقة.

لا تُخترع واجهات API أو طرق الاتصال أو آليات اعتماد النتائج قبل مراجعة الوثائق الرسمية ذات الصلة.

5. الملكية والإيرادات

الهدف هو تطوير لعبة مملوكة للمطور وتقديمها للتوزيع من خلال منصة مناسبة.

تُحدّد حقوق الملكية والتوزيع وحصة الإيرادات وآلية الدفع وفق الاتفاقية النهائية التي يقبلها المطور والمنصة.

لا يُفترض أن القبول مضمون، ولا يُفترض تحقيق دخل معين قبل القبول والتشغيل الفعلي.

6. التقنيات

- Frontend: React.
- Language: TypeScript.
- Build tool: Vite.
- Styling: CSS.
- Automated tests: Vitest، وفق الإعداد المعتمد للمشروع.

- Math model: ملف بيانات موثق ومتوافق مع المخطط الرسمي المطلوب بعد التحقق منه.

لا تُضاف قاعدة بيانات أو خدمة خلفية مستقلة إلا إذا أثبتت وثائق التكامل الرسمية الحاجة إليها.

3. حاوية الواجهة القابلة لإعادة الاستخدام.
4. تعريف الرموز وخصائصها.
5. قواعد الجولة والمكافآت والنموذج الرياضي.

7. بيانات تعريف اللعبة وإصدارها.
8. اختبارات قواعد الجولة والنموذج الرياضي والتكامل.
9. وثائق المعمارية والتقديم والاختبارات.
10. تنظيم الأصول الرسومية وحقوق استخدامها.

يجب الفصل بين واجهة العرض ومنطق اللعبة وتكامل المنصة. ولا تُعد نتيجة تُحسب في واجهة المتصفح وحدها مصدرًا موثوقًا لجولة بأموال حقيقية.
